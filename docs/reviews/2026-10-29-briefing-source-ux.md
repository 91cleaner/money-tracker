# 2026-10-29 상황실 카드 병합 후 원문·상태 UX 검토

대상: `main`의 `cards.html`, `scripts/build_briefing.py`, `data/briefing/today.json` (2026-10-29 07:46 UTC 생성). 최근 #249 병합 후 **읽기 전용 정적 검토**. 소유권: UI는 클로드, 데이터/수집기는 실장. GPT는 이 문서만 변경한다. 관련 완료 이슈: #241, #245. 별도 보안 PR #206/#213/#228과 중복되지 않는다.

## P1 — SEC·하원 신고 **행별 원문 URL이 화면에서 사라짐**

- `today.json`의 고유 카드 기준 `insider` 5행, `filings` 5행, `late` 3행, `latemove` 1행, 총 **14개 행**에 `url`이 있다. 예: insider Goldman Sachs Form 4의 `https://www.sec.gov/Archives/edgar/data/886982/000169370926000011/0001693709-26-000011-index.htm`.
- `cards.html`의 `buildCard()`는 `r.label`과 `r.value`만 span으로 추가한다. `r.url`을 읽거나 링크로 출력하지 않는다. `item()`은 카드 단위 `c.source_url`만 “출처 열기”로 노출한다.
- 따라서 Form 4/8-K 행을 눌러도 해당 신고서로 이동할 수 없고, 카드 단위 링크는 SEC **일반 검색 화면**이다. 하원 거래도 개별 PDF가 아닌 하원 신고 검색 홈으로 간다. 데이터에 보관된 원문 검증 경로를 사용자에게 전달하지 못한다.
- **클로드 수정 요청:** 각 행의 원문을 카드 밖에 접근 가능한 목록으로 표시(또는 행별 `원문 보기 / View filing` 링크). 외부 링크는 `https:` 허용목록(SEC, House Clerk 등)과 `rel="noopener noreferrer"` 적용. 행 전체를 링크로 만들면 PNG 캡처와 모바일 탭 영역을 함께 테스트. `source_url`은 카드 공통 출처로 유지하되 개별 원문 링크를 대체하지 않도록 한다.
- **회귀 조건:** Form 4 첫 행 클릭 → 해당 SEC `-index.htm`; 8-K 첫 행 → 해당 SEC 문서; 하원 거래 첫 행 → 원문 PDF. KO/EN, 375px 모바일, PNG 생성 후에도 링크가 화면에서 접근 가능해야 한다.

## P1 — 데이터 요청 실패를 ‘데이터 없음’으로 오인시킴

- `cards.html` 마지막: `fetch('data/briefing/today.json')...catch(function () { render(); });`.
- 실패해도 `data=null`인 채 `render()`되며 “오늘 보여줄 데이터가 아직 없어요.” / “No data to show yet today.”를 표시한다. **404/네트워크 실패/JSON 파싱 실패**와 실제 `top=[]`을 구별하지 못한다.
- **클로드 수정 요청:** `loadState=loading|ready|empty|error` 분리. 실패 시 “브리핑 데이터를 불러오지 못했어요. 잠시 후 다시 시도해 주세요.” / “Could not load briefing data. Please retry.” 및 재시도 버튼. 진짜 빈 응답에만 기존 empty 문구. 실패 시 날짜를 최신으로 오인하지 않도록 한다.
- **회귀 조건:** HTTP 404, 네트워크 끊김, 잘못된 JSON, 정상 빈 JSON, 정상 데이터 5가지; KO/EN·모바일 모두 구별되고 버튼이 재시도해야 한다.

## P2 — ‘어제’라는 상대 날짜가 실제 데이터 날짜와 다름

- `today.json.date=2026-10-29`, `movers.date=2026-10-27`, `movers.title_ko='어제 가장 크게 움직인 회사들'`. 10월 29일 화면에서 ‘어제’는 10월 28일로 읽힌다. `scripts/build_briefing.py`의 `build_movers()`가 제목을 고정한다.
- **실장 수정 요청:** “최근 수집된 거래일의 주가 변동” / “Biggest moves at the latest available close”처럼 상대일을 제거하고 `a.date → b.date`를 제목 또는 부제에 항상 표시. 미수집일을 실시간/당일로 오인시키지 말 것.
- **회귀 조건:** 빌드 날짜와 최신 종가 날짜가 1일/2일/휴장일 이상 차이 나는 경우 모두 실제 날짜 표시.

## P2 — 가격 출처가 공식 원문이 아닌 자체 페이지

- `build_movers()`는 `source_url='https://91cleaner.github.io/money-tracker/us.html'`로 설정한다. 이는 가격 데이터의 원천 제공자·조회 시각·수정종가 여부를 확인하는 원문이 아니다. 가격 데이터는 정책·공시와 달리 민간 가격 제공자가 필요할 수 있으므로 “공식 출처”로 포장하면 안 된다.
- **실장 수정 요청:** 실제 수집에 사용한 제공자, 기준 시각, 종가/수정종가 구분을 데이터 계약에 넣고 화면에는 “가격 자료: 제공자명 · 기준일”로 정확히 표기. 확인된 원천 URL이 없으면 “가격 원문 링크 미확인”으로 표시하고 원문처럼 자체 페이지를 내세우지 말 것.

## 배포·검증 게이트

1. 위 4건을 담당자별로 분리해 수정하고, 행별 링크/오류 상태/날짜/가격 출처 회귀 테스트 추가.
2. PNG는 정적 이미지이므로 클릭 가능한 원문 링크가 PNG에 유지된다고 주장하지 말고, 공유 본문/페이지에서 검증 경로를 제공.
3. `cards.html` 화면 375px·KO/EN·정상/오류 상태, X 공유, PNG 저장을 브라우저에서 확인.
4. GitHub Pages는 현재 **공개 저장소**이고 레거시 배포 위험이 별도 미해결. #206/#213/#228 보안 차단 및 운영 URL 재검증 전 “배포 안전” 판정 금지.
5. AI 분석과 실시간 **체결** 데이터는 미연결. 공개 PTR 신고를 확정 체결/수익률/인과관계로 오인시키지 않는다.

**이번 검증 범위:** GitHub에서 파일 원문 및 JSON 재조회, 14개 고유 행 `url` 수 확인, 코드의 링크 생성/오류 처리 경로 정적 대조. 브라우저 E2E·CI·실서비스 배포는 수행하지 않았다. 이 문서의 권고는 **코드에 아직 반영되지 않았다**.
