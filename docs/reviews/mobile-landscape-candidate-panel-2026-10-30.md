# 관제실 모바일 가로 화면: 경로 선택 패널 높이 회귀 검토 (2026-10-30)

**범위:** `world-intelligence/index.html`의 질문 → 경로 선택 → 지도 추적. GPT의 문서/코드 리뷰만 수행하며 클로드 담당 화면 파일은 변경하지 않는다.

## 확인된 코드 근거

- `#candidatePanel` 기본 CSS: `top:150px; max-height:calc(100dvh - 330px); overflow-y:auto` (현재 `world-intelligence/index.html` 약 68행).
- `@media(max-width:650px)`에서 `top:140px; max-height:calc(100dvh - 295px)` (약 73행). **가로 화면의 높이는 고려하지 않고 너비만 분기한다.**
- `showCandidates(q)`는 `candidatePanel.hidden=false`로 열지만 패널 내부에 닫기 버튼을 추가하지 않는다 (약 179~186행). 화면 상단의 별도 `처음으로` 버튼으로 빠져나갈 수는 있으므로 '완전히 닫을 수 없다'고 단정하지 않는다.
- 최근 모바일 수정 PR #362는 버튼/메뉴/언어 겹침을 수정했지만 이 패널의 높이 규칙은 그대로다.

## 재현 가능한 정적 CSS 계산

| 뷰포트 (CSS px) | 적용 규칙 | 계산된 `max-height` | 위험 |
| --- | --- | --- | --- |
| 844 × 390 (휴대폰 가로) | 기본 (>650px) | **60px** | 여러 경로를 선택하기 위해 아주 작은 스크롤 영역 사용 |
| 667 × 375 (휴대폰 가로) | 기본 (>650px) | **45px** | 경로 버튼 하나의 높이보다 작을 수 있음 |
| 640 × 360 (좁은 가로) | 모바일 (≤650px) | **65px** | 패널이 매우 짧음 |
| 375 × 667 (세로) | 모바일 (≤650px) | 372px | 같은 문제가 상대적으로 작음 |

위 값은 코드의 CSS 식으로 계산한 결과다. **실제 브라우저/실기기 렌더링과 클릭 성공 여부는 아직 검증하지 않았다.** `max-height`는 콘텐츠 자체의 최종 높이와 같다고 단정할 수 없다.

## 클로드 담당 수정 제안

1. `@media (orientation:landscape) and (max-height:500px)`에서 패널 `top`을 헤더 바로 아래로 낮추고, `max-height`를 실제 남은 뷰포트 높이와 `env(safe-area-inset-*)`로 계산한다. 기존 세로 레이아웃은 유지한다.
2. 패널 제목 줄에 명시적 **닫기** 버튼을 제공하고, `Escape`로 닫을 수 있게 한다. 닫으면 지도의 현재 위치를 유지한다.
3. 경로 선택 버튼은 손가락 터치가 가능한 크기를 유지한다. 패널 내부 스크롤이 가능해야 하고 하단 컨트롤/재생 버튼과 겹치면 안 된다.
4. 지도 선택 경로가 공식 데이터가 아닌 시연 경로인 경우 **'AI 분석 미연결 · 실시간 거래 데이터 미연결'** 문구를 유지한다. 데이터 조회 실패를 '거래 0건'으로 바꾸지 않는다.

## 수락 기준 / QA

- 844×390, 667×375, 640×360, 375×667, 320×568에서 **질문 → 후보 2개 이상 표시 → 아래 후보 터치 → 지도 이동 → 닫기 → 다른 후보 재선택**을 수동 검증한다.
- iOS Safari 및 Android Chrome에서 주소창 높이 변화, 노치 안전 영역, 가로 회전 후 스크롤·클릭·키보드 닫힘을 확인한다.
- 후보 패널이 1개 버튼보다 짧은 스크롤 창으로 축소되지 않고, 닫기 컨트롤이 항상 보이는지 확인한다.
- 한국어/영어 양쪽에서 텍스트 줄바꿈과 터치 타깃을 확인한다.
- CI 정적 검사만으로는 실제 화면 적합성을 보장할 수 없으므로 브라우저/실기기 결과를 별도로 기록한다.
