# 독립 코드 리뷰: 미국 회사·의원 상세 화면 (2026-10-28 14:56 KST)

**범위:** Claude 작업 중인 PR [#148](https://github.com/91cleaner/money-tracker/pull/148) `company.html`과 [#151](https://github.com/91cleaner/money-tracker/pull/151) `member.html`. GPT는 담당 분담(`docs/AI-ROLES.md`)에 따라 **리뷰 문서만** 작성하며, 화면·수집기·`data/`를 수정하지 않는다. PR 두 건에 코드 리뷰 의견도 각각 남겼다.

## P1 — 회사 상세의 '1달' 종가 수익률 기준일 오류 (PR #148)

**위치:** `company.html`의 `shiftMonth(iso)` → `priceBlock`의 `onOrBefore(rows, shiftMonth(last.d))`.

- 실제 코드: `new Date(iso + "T00:00:00Z").setUTCMonth(getUTCMonth() - 1)`.
- 재현(UTC): `2026-03-31`에서 한 달 전을 계산하면 `2026-03-03`이 된다. 전월 마지막 날인 `2026-02-28`이 아니다.
- 결과: 화면의 **1달** 수익률이 28일가량의 기준일이 아니라 3월 3일 종가 기준으로 계산될 수 있다. 투자 데이터 날짜 표시의 정확성 문제다.
- 권고: 이전 달의 동일 일자, 없으면 **이전 달 마지막 날**로 clamp. 거래일이 아니면 그 날짜 이전의 가장 가까운 거래일을 선택하되 기준일을 사용자에게 알릴 것.
- 테스트: 2026-03-31 → 2026-02-28, 2026-05-31 → 2026-04-30, 2024-03-31 → 2024-02-29.
- 추가: `ytdBase`는 전년 말 자료가 없으면 당해 첫 종가를 쓰면서 '연초 대비'라고 표시한다. 이때는 '보유 자료 시작일 대비'로 정확히 표기하거나 비교값을 숨길 것.

## P1 — 의원 상세의 자료 불러오기 실패를 '기록 없음'으로 표시 (PR #151)

**위치:** `member.html`의 `get(p)`와 `Promise.all` 결과 처리.

- 실제 코드: `get`은 HTTP 404, 네트워크 실패, JSON 오류를 모두 `null`로 바꾸며, `tr.trades || []`와 `mem.members || []`는 실패와 정상적인 빈 배열을 구분하지 않는다.
- 결과: 공시 파일 요청이 실패한 상황에서도 '의원을 찾지 못했습니다' 또는 '이 의원의 거래 신고 기록이 저장소에 없습니다'로 보인다. **미연결 ≠ 0건** 원칙 위반.
- 권고: 필수 파일 로드 상태를 `ok / unavailable / invalid`로 구분하고, 실패 시 '공개 자료를 불러오지 못했습니다. 기록 0건을 뜻하지 않습니다'와 재시도 기능을 표시한다. 선택 파일 실패 시 일부만 표시한다면 해당 섹션에 '자료 미연결'을 붙일 것.
- 테스트: (1) 404, (2) JSON 파싱 실패, (3) 정상 `{"trades":[]}` 각각 화면 문구가 달라야 한다. 기존 공개 신고 건수는 임의 보정하지 않는다.

## 검증·인계

- 확인한 것: GitHub의 해당 PR 코드와 `HANDOFF.md`, `docs/AI-ROLES.md`를 읽었고, Node.js UTC 날짜 계산으로 3/31 → 3/03을 재현했다. 두 PR에 검토 의견을 게시했다.
- 확인하지 못한 것: Claude 수정 후의 브라우저 동작, PR 병합, 실서비스 배포. **이 문서는 기능 수정 완료 보고가 아니다.**
- 작업 소유: 두 문제 모두 해당 Claude PR 작성자가 수정·테스트한 뒤 운영자 검토로 병합. GPT는 별도 코드 변경·원본 데이터 변경 없이 후속 검증만 수행.
- 미연결: AI 생성 분석과 실시간 체결 데이터는 미연결이며, 과거 공개 공시와 종가만 사실 기반으로 표시해야 한다.
