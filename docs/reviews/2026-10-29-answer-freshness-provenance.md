## P1: 가격 계열 선택 기준이 '최신 날짜'가 아니라 '행 수'

`scripts/analyze/common.py::load_series()`는 `data/us/prices/YYYY-MM-DD.json`을 읽은 뒤 `data/markets/*.json`의 행 수가 더 많으면 그 장기 계열로 **교체**한다.

```python
if key not in ser or len(ser[key][0]) < len(pair[0]):
    ser[key] = pair
```

이 로직은 장기 계열이 하루 이상 늦더라도 더 길다는 이유로 최신 종가를 버린다. **실제 `main` 파일에서 다음과 같이 재현된다.**

| 경로 | 확인된 값 |
| --- | --- |
| `data/markets/NVDA.json` | 2,511행, 마지막 `2026-10-26`, 종가 `216.00`, 출처 필드 `yahoo` |
| `data/us/prices/NVDA.json` | 218행, 마지막 `2026-10-27`, 종가 `217.94` |
| `data/us/prices/2026-10-27.json` | `c.NVDA = 217.94` |
| `data/answers/NVDA.json` | `asof = 2026-10-26`, `last = 216` |

따라서 10월 27일 자료가 존재하는데도 10월 26일 종가가 답변에 사용된다. 관측 가격 차이는 **$1.94**이다. 이를 시장 데이터의 진위나 실시간 시세로 주장하지 않는다. 파일에 저장된 값과 로더의 선택 규칙을 대조한 결과다.

### 권고 수정·회귀 조건 (담당: 실장/클로드)

1. **최신 날짜를 비교**한다. 단순히 배열 길이만 비교해서 출처를 선택하지 않는다.
2. 두 출처의 `adjusted` 여부, 통화, 종목 매핑이 같다고 확인하기 전에는 가격 계열을 무조건 이어 붙이지 않는다. 확인 불가 시 해당 기간을 **불완전/지연**으로 표시하고 검증 불가능한 수익률은 숨긴다.
3. 회귀 테스트 A: 장기 `2026-10-26`(2,511행) vs 단기 `2026-10-27`(218행) → 더 최신인 자료를 무시하지 않을 것.
4. 회귀 테스트 B: 단기 출처가 더 오래되면 오래된 값으로 최신 종가를 덮지 않을 것.
5. 회귀 테스트 C: 조정종가·통화·가격 단위 불일치 시 결합 거부 및 사용자에게 제한 표시.
6. 생성 답변의 `asof`와 선택한 출처의 마지막 날짜가 일치하는지 별도 검사.

## P1: 출처 링크 존재 검사만으로 공식 원문·가격 출처를 보장하지 못함

`scripts/analyze/build.py`는 모든 종목에 `src = ["https://finance.yahoo.com/quote/" + sym]`을 붙이고, `verify.py`는 `src`가 비어 있지 않은지만 확인한다. 정책 사건 원문은 `events[].u`에 있지만, 주가 출처는 민간 금융 서비스 링크다.

- **정부 정책·법안·의원 거래:** 실제 공식 원문 링크만 표시.
- **주가:** 민간 데이터 제공처와 가격 기준일·조정 여부를 명시하고, 정부 공식 자료인 것처럼 표현하지 않기.
- **분석:** 미리 계산된 정적 템플릿이며 실시간 AI 분석이 아님. **AI 미연결 / 실시간 체결 미연결**을 독립적으로 표시.
- `verify.py`에 URL 스킴 검사뿐 아니라 출처 유형 및 기준일의 필수 필드 검증을 추가할 것. 동일 `load_series()`를 생성기·검증기가 같이 쓰므로, 자기 일치 검사는 **원본 중 가장 최신 날짜**를 사용했는지 보증하지 못한다.
