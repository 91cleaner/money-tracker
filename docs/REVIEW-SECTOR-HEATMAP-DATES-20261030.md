## P1-1 — '같은 기간'이라고 표시하지만 신고와 주가 기간은 독립적

**재현 가능한 코드 경로**
- `sector-board.html` 메타 설명(5~8행)은 **"업종별 최근 7일 의원 거래 신고 수와 같은 기간 종가 변화"**라고 주장.
- 약 150~158행: 신고 기간은 `data/us/trades_public.json`의 `trades[].filed` **최댓값**을 `end`로, 그 6일 전을 `start`로 정함. 오늘 기준 최근 7일도, 가격 기준일 기준 7일도 아님.
- 약 157~162행: 가격은 별도 `data/us/prices/summary.json`의 `t[ticker].w1`을 사용. 이 값의 기간은 `pr.date` 기준 1주이며, 신고 기간과 같은 날짜라는 검증이 없음.
- 실제 `main`의 가격 요약은 `date: 2026-10-28` (출처 표기: Massive/구 Polygon 수정종가). 신고 데이터의 최신 신고일이 같은 주인지 검증하지 않아 **기간 불일치 시에도 나란히 비교**함.

**수정 수락 기준 (클로드 UI + 실장 데이터 확인)**
1. 신고 카드에 **"데이터에 기록된 최근 신고일 기준 7일: YYYY-MM-DD ~ YYYY-MM-DD"**, 가격 카드에 **"종가 1주 변화: YYYY-MM-DD 기준"**을 **각각** 표시. 동일 기간이라고 주장하지 않음. 메타 설명도 동일하게 수정.
2. `pr.date` 누락/잘못된 형식 또는 신고 최신일과 가격 기준일의 간격이 클 때 **"기간 불일치 · 직접 비교 주의"**를 표시. 임의로 날짜를 보정하거나 과거 수치를 오늘 수치처럼 표시하지 않음.
3. `filed`가 미래 날짜이거나 형식이 틀리면 그대로 최신 기준일로 채택하지 말고 원문 대조/검증 대기로 분리.
4. 출처에 **하원 PTR은 사후 신고**, 주가 요약은 **제3자 제공 가격 데이터**라는 점을 구분. 시간적 근접성은 인과관계·투자 신호가 아님.

## P1-2 — HTTP 오류·네트워크 실패를 '신고 자료 없음'으로 오표시

**재현 가능한 코드 경로**
- `sector-board.html`의 `get(p)`는 `!r.ok`와 `catch` 모두 `null`을 반환.
- `Promise.all` 이후 `tr = r[2] || {}`, `trades = tr.trades || []`로 바꾸고 `!filed.length`이면 **"신고 자료가 없습니다."**를 출력.
- 즉 `data/us/trades_public.json` 404/403/500, JSON 파싱 실패, 연결 실패와 **정상 수집 결과 0건**이 동일한 사용자 메시지로 표시됨. 검색·검증 중 자료 누락을 숨길 수 있음.

**수정 수락 기준**
1. 각 입력의 `ok/error/missing/empty` 상태를 분리. 특히 신고 데이터 요청 실패 시 **"신고 자료를 불러오지 못했습니다. 다시 시도"**와 재시도 동작 제공.
2. 정상 응답 `trades: []`일 때만 **"현재 확인된 신고 항목 0건"**. 이 문구도 '의원 거래 자체가 0건'이라는 의미가 아님을 명시.
3. `ticker-sectors.json` 또는 가격 요약 실패 시에도 전체를 0건으로 간주하지 말고 해당 업종/가격 칸에 **"자료 연결 실패"**를 표시.
4. 모바일 폭 375px에서 실패 상태·재시도 버튼·기준일을 확인하고, 키보드 접근 가능한 버튼으로 구현.

## P2 — '최대 45일 차이'는 실제 모든 신고의 상한이 아님

약 168행의 **"거래일→신고일 최대 45일 차이가 있을 수 있습니다"**는 지연 신고 사례에서 45일 초과 가능성을 지움. 권장 문구: **"하원 PTR은 거래 후 공개되는 신고 자료입니다. 거래일과 신고일은 다르며 지연 신고가 있을 수 있습니다. 개별 원문에서 날짜를 확인하세요."** '지연 신고' 여부는 개별 원문과 규정에 따라 검증.
