# 2026-10-29 세계 관제실 3개월 주가·기간 일치성 코드 리뷰

대상: `main`에 병합된 #260, #261 이후 `world-intelligence/index.html`의 `mt-console-js`, `data/us/prices/summary.json`, `data/us/prices/AAPL.json`. 기존 #259(3달 다이얼 구현), #251(브리핑 카드 원문/오류 상태), #218(분석 엔진 시계열 선택), #206/#213/#228(Pages 보안)과 **별개인 관제실 가격 표시 정확성**만 검토한다. `docs/AI-ROLES.md`에 따라 GPT는 화면/수집기 코드를 변경하지 않고 검토·수락 기준만 기록한다.

## P1 — 가격과 지도 사건의 비교 기간이 서로 달라도 “같은 기간”이라고 표기

- `calc(m)`의 사건 필터 시작점은 `ref(m)` (현재 경로의 최신 사건 날짜)에서 `period * 864e5`를 뺀 날짜다.
- `pct(m)`의 1주·1달은 `summary.json`의 `w1/m1`, 3달은 `load3()`가 **가격 파일 마지막 날짜**에서 90일을 뺀 날짜를 기준으로 계산한다. 사건 기준일과 가격 기준일의 일치 여부는 확인하지 않는다.
- `paint()`는 이 둘을 합쳐 “같은 기간 주가” / “price change over the same period”라고 표시하며 가격 기준일을 표시하지 않는다. 사건의 최신 날짜가 가격의 `as_of`와 다르면 기간이 같지 않다. **코드 경로상 재현 가능한 조건부 정확성 결함**이며 실제 경로별 발생 건수는 미측정이다.
- 확인된 실제 파일: `summary.json.date = 2026-10-27`, `AAPL.json.as_of = 2026-10-27`. AAPL 3달 계산은 `2026-07-29` 종가 `338.19`에서 `2026-10-27` 종가 `347.10`까지 약 **+2.63%**다. 10/29 최신 실시간 수치가 아니다.
- **클로드(UI) 수락 조건:** 사건 필터 기준일과 가격 수익률의 시작·종료일을 별도 표시. 날짜가 실제로 같을 때만 “같은 기간”; 다르면 “지도 사건: [시작~끝] / 주가: [시작~끝]”처럼 비교 범위를 명시. KO/EN 모두 “today/live/current” 금지. 375px 화면에서 날짜가 잘리지 않게 할 것.
- **실장(데이터) 수락 조건:** 가격 시계열의 `as_of`와 `summary.date`가 일치하는지 빌드 단계 검증. 일치하지 않으면 계산을 중단하거나 ‘기간 불일치’ 상태로 제공. 가격 데이터는 Massive(구 Polygon) 종가 계열이며 공식 의회 공시와 다른 출처임을 명시.

## P1 — 3개월 가격 파일이 있어도 summary에 종목이 없으면 조회조차 하지 않음

- 현재 `pct(m)`: `const k=tk(m),x=P&&P.t&&P.t[k]; if(!x)return''; if(period===90){load3(k);...}`.
- 즉 `data/us/prices/<TICKER>.json`이 존재해도 `summary.json.t[TICKER]`가 누락되면 90일 분기 자체에 진입하지 않는다. `summary.json` 로딩 실패 때도 동일하다. **정적 코드로 확인된 누락 시나리오**이며 실제 종목 누락 건수는 미측정이다.
- **클로드(UI) 수락 조건:** 90일 계산은 유효한 티커·가격 시계열 파일의 존재로 판단하고, `summary.t[k]`가 필요한 7일/30일 계산과 분리. 누락/오류/준비 중 상태를 분명히 구분; 3달 자료가 실제로 있을 때 빈 숫자를 출력하지 말 것.
- **회귀:** `P=null`이나 `P.t.AAPL` 삭제, `AAPL.json` 정상 제공 → 3달 수치가 정상 표시; 7일/30일은 “자료 없음”으로 표시. 파일이 없으면 수치를 꾸미지 말 것.

## P2 — 일시적 fetch 오류를 영구적인 “준비 중”으로 고정

- `load3(k)`는 최초 요청 시 `M3[k]=undefined`, 요청 실패 시 `M3[k]=null`로 저장한다. 다음 요청은 `if(!k||k in M3)return`에 막혀 **같은 페이지에서 재시도 불가**.
- 화면에서는 `soon(m)`이 `null`을 “3달 주가는 준비 중 / 3-month prices coming soon”으로 표시한다. 네트워크 일시 오류와 진짜 미수집을 구별하지 못한다.
- **클로드(UI) 수락 조건:** `loading/ready/unavailable/error` 상태 분리, 실패 시 “가격 자료를 불러오지 못했어요 / Could not load price data”와 재시도. 정상 404는 “이 종목의 3개월 자료 없음”, 데이터 기간 부족은 “90일 미만”으로 분리. 실패한 요청은 재시도 가능해야 한다.
- **회귀:** 최초 503 → 재시도 200, 최초 오프라인 → 온라인, 404, 잘못된 JSON, 90일 미만, 정상 AAPL JSON. 정상 수치는 가격의 마지막 거래일과 시작일을 함께 표시.

## 배포·검증 게이트

1. 클로드 담당 화면 수정은 별도 브랜치/PR로 진행; 실장 소유 `data/`와 수집기 파일은 건드리지 않는다. #259 완료분을 다시 만들지 않는다.
2. `node` 단위 테스트: 기간 기준일 불일치, 90일 summary 누락, 네트워크 실패 후 재시도, 유효하지 않은 숫자/날짜가 `NaN%`로 노출되지 않음. KO/EN 문자열을 모두 확인.
3. 브라우저 375×667, 390×844, 데스크톱에서 질문→회사 선택→지도 경로→기간 1주/1달/3달→재생·닫기까지 실제 조작 검증. 지도/브리핑 겹침과 가격 기준일 가시성 확인.
4. Pages 실제 배포는 공개 저장소·레거시 배포 보안 문제(#206/#213/#228) 해결 전 안전 판정 금지. AI 분석과 **실시간 체결 데이터는 미연결**. PTR은 공개 신고이며 실거래 확인이 아니다.

**검증 수준:** GitHub 원본 소스/가격 JSON 정적 대조 및 AAPL 90일 산식 확인. 화면 코드는 변경하지 않았고, 브라우저 E2E·CI·운영 배포는 실행하지 않았다. 위 3건은 수정 제안이며 해결 완료를 뜻하지 않는다.
